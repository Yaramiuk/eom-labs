## Підготовка

arithmetic.c вивела Result: 12.

Що має зробити CPU для int result = a + b: взяти a з пам'яті, взяти b, скласти їх і записати результат туди, де лежить result.

## Завдання 1. Отримуємо Assembly

Команда gcc -Wall -Wextra -O0 -S arithmetic.c -o arithmetic.s. Файл вийшов на 37 рядків, хоча в програмі кілька рядків. Там багато директив типу .file, .section, .cfi_*.

Знайшов функцію main, інструкції movl $5, -4(%rbp) і movl $7, -8(%rbp), додавання addl %edx, %eax, виклик call printf і ret.

Відповіді:
- Ні, не кожному рядку C відповідає одна інструкція. int a = 5 це один mov, а result = a + b це чотири інструкції (два mov, add і ще mov).
- Змінних a, b, result в Assembly немає. Є тільки місця в стеку: a це [rbp-4], b це [rbp-8], result це [rbp-12].
- Тіло main займає приблизно 17 інструкцій.
- Додавання є, це add.

## Intel syntax

З -masm=intel виглядає зрозуміліше:

```
main:
	push	rbp
	mov	rbp, rsp
	sub	rsp, 16
	mov	DWORD PTR [rbp-4], 5
	mov	DWORD PTR [rbp-8], 7
	mov	edx, DWORD PTR [rbp-4]
	mov	eax, DWORD PTR [rbp-8]
	add	eax, edx
	mov	DWORD PTR [rbp-12], eax
	mov	eax, DWORD PTR [rbp-12]
	mov	esi, eax
	mov	edi, OFFSET FLAT:.LC0
	mov	eax, 0
	call	printf
	mov	eax, 0
	leave
	ret
```

В Intel спочатку куди, потім звідки, і немає % та $. В AT&T навпаки і ще суфікси типу movl.

## Завдання 2. Арифметична операція

operations.c вивела 30. У функції calculate a приходить в edi, b в esi, складання робиться в eax. Результат повертається теж в eax.

Потім міняв операцію:

| C | Основна інструкція |
|---|---|
| a + b | add eax, edx |
| a - b | sub eax, DWORD PTR [rbp-24] |
| a * b | imul eax, DWORD PTR [rbp-24] |

Змінилась тільки одна інструкція посередині, все інше (пролог, збереження параметрів, ret) таке саме. Для sub і imul компілятор взяв другий операнд прямо з пам'яті, без edx.

## Завдання 3. if

condition.c вивела 20. Функція max_value:

```
	mov	eax, DWORD PTR [rbp-4]
	cmp	eax, DWORD PTR [rbp-8]
	jle	.L2
	mov	eax, DWORD PTR [rbp-4]
	jmp	.L3
.L2:
	mov	eax, DWORD PTR [rbp-8]
.L3:
	pop	rbp
	ret
```

| C | Assembly |
|---|---|
| if (a > b) | cmp eax, [rbp-8] і jle .L2 |
| return a | mov eax, [rbp-4] і jmp .L3 |
| else | мітка .L2 |
| return b | mov eax, [rbp-8] |

Інструкції IF немає. Спочатку cmp порівнює і ставить прапорці, потім умовний перехід дивиться на прапорці і або стрибає, або ні. Компілятор перевернув умову: замість a > b перевіряє a <= b і стрибає на else. В кінці першої гілки стоїть jmp, щоб не виконати else.

## Завдання 4. Цикл

loop.c вивела 15. sum_to:

```
	mov	DWORD PTR [rbp-4], 0
	mov	DWORD PTR [rbp-8], 1
	jmp	.L2
.L3:
	mov	eax, DWORD PTR [rbp-8]
	add	DWORD PTR [rbp-4], eax
	add	DWORD PTR [rbp-8], 1
.L2:
	mov	eax, DWORD PTR [rbp-8]
	cmp	eax, DWORD PTR [rbp-20]
	jle	.L3
```

Спочатку sum = 0 і i = 1, потім jmp одразу на перевірку. На .L2 порівняння i з n, і якщо i <= n, стрибок назад на .L3, де тіло і i++.

- Порівняння робить cmp.
- Перехід робить jle (назад у цикл), на початку ще є jmp до перевірки.
- Слова for в Assembly немає, тільки мітки і переходи.
- CPU повторює цикл, бо після cmp прапорці кажуть, що i <= n, і jle стрибає назад.

Цікаво, що перевірка стоїть після тіла, а на початку один jmp до неї.

## Завдання 5. Виклик функції

У main перед call calculate кладеться edi = 10 і esi = 20. Сам call за адресою 0x401152. calculate починається з 0x401126, закінчується pop rbp і ret на 0x40113f. Результат повертається в eax.

Повертатися потрібно в різні місця, бо функцію можуть викликати звідки завгодно. Тому call кладе адресу наступної інструкції на стек, а ret її звідти забирає.

## Завдання 6-7. Machine code

objdump -d -M intel operations, функція calculate:

```
  401126:	55                   	push   rbp
  401127:	48 89 e5             	mov    rbp,rsp
  40112a:	89 7d ec             	mov    DWORD PTR [rbp-0x14],edi
  40112d:	89 75 e8             	mov    DWORD PTR [rbp-0x18],esi
  401130:	8b 55 ec             	mov    edx,DWORD PTR [rbp-0x14]
  401133:	8b 45 e8             	mov    eax,DWORD PTR [rbp-0x18]
  401136:	01 d0                	add    eax,edx
  401138:	89 45 fc             	mov    DWORD PTR [rbp-0x4],eax
  40113b:	8b 45 fc             	mov    eax,DWORD PTR [rbp-0x4]
  40113e:	5d                   	pop    rbp
  40113f:	c3                   	ret
```

| Address | Bytes | Assembly |
|---|---|---|
| 0x401136 | 01 d0 | add eax, edx |
| 0x401152 | e8 cf ff ff ff | call 401126 <calculate> |
| 0x40113f | c3 | ret |

У call після e8 іде зміщення 0xffffffcf, це -49. Наступна інструкція на 0x401157, і 0x401157 - 49 якраз дає 0x401126, тобто початок calculate.

Відповіді:
- У виконуваному файлі лежить machine code, тобто байти. Тексту Assembly там немає.
- objdump показує Assembly, бо він дизасемблер і перекладає байти назад, щоб людина могла прочитати.
- Інструкції різної довжини: ret 1 байт, add 2, mov rbp,rsp 3, call 5.
- Assembly читати легше, ніж байти, бо там видно назви інструкцій і регістрів.

## Завдання 8. -O0 і -O2

З -O2 calculate стала такою:

```
calculate:
	lea	eax, [rdi+rsi]
	ret
```

А в main взагалі немає call calculate, там просто mov esi, 30. Компілятор вбудував функцію і порахував результат сам.

| | -O0 | -O2 |
|---|---|---|
| calculate | 11 інструкцій, все через стек | 2 інструкції |
| додавання | add | lea |
| call calculate | є | немає |
| обнулення eax | mov eax, 0 | xor eax, eax |

Тобто один і той самий C-код може дати зовсім різний Assembly.

## Завдання 9. return 10 + 20

Так і є, і навіть на -O0 там mov eax, 30 без жодного add. На -O2 ще й main стала просто mov eax, 30 і ret. Як я зрозумів, константи gcc складає завжди, навіть без оптимізації. Компілятор має на це право, бо результат програми від цього не змінюється.

## Фінальне завдання analyze.c

Написав функцію range_score(x, y): через if/else визначає менше і більше число (lo і hi), потім у циклі додає k * 2 для k від lo до hi і повертає total - lo. Для range_score(7, 3) вийшло 47 (2*(3+4+5+6+7) - 3 = 50 - 3).

Що знайшов в objdump:

| порівняння | 0x401133, 0x401170 | cmp |
| умовний перехід | 0x401136, 0x401173 | jge (if), jle (цикл) |

## Контрольні питання

1. ISA це набір інструкцій процесора, його регістри і як інструкції кодуються в байти. Наприклад x86-64 або ARM64.
2. CPU не може виконувати C, бо він розуміє тільки машинні інструкції своєї ISA. C треба спочатку скомпілювати.
3. Machine code це байти (01 d0), а Assembly це текстовий запис тих самих інструкцій (add eax, edx).
4. -S зупиняє компіляцію на етапі Assembly і зберігає .s файл.
5. -O0 вимикає оптимізацію, тому Assembly простіше зіставити з C.
6. Operand це те, з чим працює інструкція: регістр, число або пам'ять.
7. mov копіює дані між регістрами, пам'яттю і константами.
8. cmp віднімає одне від іншого без збереження результату і ставить прапорці.
9. if робиться через cmp і умовний перехід, плюс jmp в кінці першої гілки.
10. Цикл робиться через мітку, cmp і перехід назад.
11. call викликає функцію: кладе адресу повернення на стек і стрибає на функцію.
12. ret бере адресу повернення зі стеку і повертається туди.
13. Один рядок C може робити кілька дій (прочитати, порахувати, записати), тому інструкцій буває кілька. Або навпаки, після оптимізації рядки можуть злитися чи зникнути.
14. objdump -d показує адреси, байти і Assembly для кожної інструкції.
15. З -O2 компілятор оптимізує: тримає змінні в регістрах, вбудовує функції, рахує константи заздалегідь. Тому код сильно відрізняється від -O0.
16. Так, компілятор може видалити частину коду, якщо від цього не змінюється результат програми. Наприклад непотрібні обчислення або виклик, який можна замінити готовим числом.

## Висновок

Я подивився, як C перетворюється в Assembly і далі в байти. Змінних, if і for на рівні процесора немає: є адреси в стеку, cmp і переходи. Функції викликаються через call і ret, аргументи передаються в edi і esi, а результат повертається в eax. Ще побачив, що -O2 може дуже змінити код: функцію вбудувало, а результат порахувало ще при компіляції.
