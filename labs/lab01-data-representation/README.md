# Lab 1. Представлення даних у пам'яті комп'ютера

Робив на своєму MacBook (Apple Silicon, arm64), компілятор Apple Clang 21, але викликав його через gcc. Кожну програму компілював так: gcc -std=c11 -Wall -Wextra types.c -o types і запускав ./types, з іншими файлами так само.

## 1. Розміри типів

Розміри дивився через sizeof. Біти рахував як sizeof * 8.

| Тип | Байти | Біти |
|---|---|---|
| char | 1 | 8 |
| short | 2 | 16 |
| int | 4 | 32 |
| long | 8 | 64 |
| long long | 8 | 64 |
| float | 4 | 32 |
| double | 8 | 64 |
| void * | 8 | 64 |

Типи мають різний розмір. Вказівник займає 8 байтів, бо система 64-бітна. Цікаво, що long і long long тут однакові.

## 2. Decimal, hex, binary

| Decimal | Hex | Binary |
|---|---|---|
| 10 | 0x0A | 00001010 |
| 65 | 0x41 | 01000001 |
| 127 | 0x7F | 01111111 |
| 255 | 0xFF | 11111111 |
| 256 | 0x100 | 00000001 00000000 |
| 1024 | 0x400 | 00000100 00000000 |

Це одне й те саме число, просто записане в різних системах числення. Одна hex-цифра це рівно 4 біти, тому hex зручно читати замість довгого двійкового запису.

## 3. Виведення бітів

binary.c друкує 8 бітів для 0, 1, 10, 65, 127, 128 і 255. Цикл іде від біта 7 до біта 0, щоб старший біт був зліва. Кожен біт отримую зсувом вправо і маскою & 1.

## 4. Символи

| Символ | Decimal | Hex |
|---|---|---|
| A | 65 | 0x41 |
| B | 66 | 0x42 |
| a | 97 | 0x61 |
| 0 | 48 | 0x30 |
| 9 | 57 | 0x39 |

У char c = 'A' насправді лежить число 65. Тільки %c виводить його як букву.

## 5. Signed та unsigned

Перед запуском думав, що -1 в int8_t буде 11111111, як і 255 в uint8_t. Так і вийшло: обидва дали 0xFF і однакові біти 11111111, а виводилось -1 і 255. Тобто біти однакові, а значення залежить від типу.

## 6. Межа uint8_t

Очікував, що після 255 буде 0, бо в 8 бітах всього 256 значень. Результат: 254, 255, потім 255 + 1 = 0 і 255 + 2 = 1. Unsigned рахує по модулю 256. Але для signed так робити не можна, там переповнення це undefined behavior.

## 7-8. Байти в пам'яті та endianness

Для uint32_t value = 0x12345678 при big-endian байти йшли б 12 34 56 78, а при little-endian навпаки 78 56 34 12. У мене вийшло byte 0 = 0x78, byte 1 = 0x56, byte 2 = 0x34, byte 3 = 0x12. Адреси йдуть підряд, і першим лежить молодший байт, тобто моя система little-endian. Саме число при цьому не змінюється, змінюється тільки порядок байтів у пам'яті.

## 9. Один набір бітів

| Як читати 01000001 | Значення |
|---|---|
| binary | 01000001 |
| hex | 0x41 |
| unsigned decimal | 65 |
| ASCII | A |

Комп'ютер сам не знає, що означають біти. Це визначає тип або контекст.

## 10. inspect.c

Програма читає число від 0 до 255 і виводить його в decimal, hex, binary і як символ, якщо він друкований. Ще вона показує байти 0x12345678 з адресами і сама визначає порядок байтів. Для 65 вивела Decimal 65, Hexadecimal 0x41, Binary 01000001, Character A.

## Контрольні питання

1. Біт це одна цифра 0 або 1, байт це 8 бітів.
2. n бітів дають 2^n значень.
3. 8-бітний unsigned: від 0 до 255.
4. 8-бітний signed (two's complement): від -128 до 127.
5. Hex зручний тим, що одна цифра це 4 біти, тому запис короткий.
6. 11111111 як uint8_t це 255, як int8_t це -1.
7. Якщо до uint8_t 255 додати 1, буде 0.
8. Для 'A' зберігається код 65 (0x41).
9. Endianness це порядок байтів багатобайтового числа в пам'яті.
10. У моєї системи little-endian.
11. sizeof(int) показує, скільки байтів займає int. У мене 4.
12. Ті самі біти можуть бути різними даними, бо все залежить від типу, через який їх читають.

Побачив, що uint8_t після 255 переходить у 0, а моя система little-endian. Головне, що я зрозумів: у пам'яті просто біти, а що вони означають, вирішує програма через тип.
